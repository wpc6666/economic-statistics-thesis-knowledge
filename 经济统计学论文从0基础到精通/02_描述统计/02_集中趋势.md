# 02 集中趋势：数据"中间"在哪？

## 一、为什么要学这个？

新闻说："2023 年全国城镇居民人均可支配收入 51821 元。"

你看完的第一反应是什么？

- A："哦，我家差不多这个数。"
- B："我怎么觉得我和周围的人都没到 5 万？是不是我拖后腿了？"
- C："等等，这个'人均'是怎么算的？是所有人加起来除以人数吗？那马云一个人进来，不就把平均值拉到天上去了？"

**选 C 的人，已经在想"集中趋势"了。**

"人均收入 5 万"这个数字，其实是在回答一个问题：**城镇居民的收入，集中在哪个水平？**

但问题是——"集中"这个词，有三种不同的算法：
- 把所有人的收入加起来除以人数 → **均值**；
- 把所有人按收入排队，站中间的那个人 → **中位数**；
- 出现次数最多的那个收入 → **众数**。

**这三个数，说的都是"中间在哪"，但结果可能天差地别。**

不学会怎样？你写论文时写"样本平均工资为 8000 元"，导师问你："这个均值是被几个高管拉高的，还是真的大多数人都在 8000？"——你答不上来。

## 二、是什么？

### 生活比喻：酒吧里的收入

想象一个酒吧里有 10 个顾客，他们的月收入分别是：

```
3000  3500  4000  4500  5000  5500  6000  6500  7000  8000
```

**均值**：加起来除以 10 = 53000 / 10 = **5300 元**。
意思：酒吧里每个人"平均"收入 5300 元。

**中位数**：排队后第 5 个和第 6 个的平均 = (5000 + 5500) / 2 = **5250 元**。
意思：一半人收入低于 5250，一半人高于 5250。

现在——**马云走进来了。**

马云的月收入假设是 1 亿元。

重新算：

**均值**：(53000 + 100000000) / 11 = **约 909 万元**。
意思："酒吧里每个人平均收入 909 万。"——这个数根本不能代表任何人，除了马云自己，没人到这个数。

**中位数**：11 个人排队，第 6 个是谁？还是原来的 5500 元。
意思：一半人收入低于 5500，一半人高于 5500。——这个结论还成立。

**这就是为什么说收入要用中位数，不用均值。**

### 严格定义

| 统计量 | 定义 | 公式 |
|--------|------|------|
| **[[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP01_算术平均数简单与加权|均值]]** $\bar{x}$ | 所有值加起来除以个数 | $\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i$ |
| **[[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP05_中位数|中位数]]** $M_e$ | 排序后站中间的那个值 | 奇数个：第 $(n+1)/2$ 个；偶数个：第 $n/2$ 和 $n/2+1$ 个的平均 |
| **[[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP04_众数|众数]]** $M_o$ | 出现次数最多的值 | 不需要公式，数频数 |

> 教材里除了这三个，还会讲 [[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP02_调和平均数|调和平均数]] 和 [[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP03_几何平均数|几何平均数]]——前者在"已知单价、已知金额"的平均价格问题里用，后者在算平均增长率、平均利率时用。论文里用得少，但考试常考。

### 三者的关系（偏态时谁大谁小）

[[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP06_均值中位数众数关系|均值、中位数、众数三者的大小关系]]和分布形状直接挂钩：

- **对称分布**：均值 ≈ 中位数 ≈ 众数，三线重合；
- **右偏分布**（尾巴拖向大值，如收入）：均值 > 中位数 > 众数（均值被大值拉到最右边）；
- **左偏分布**（尾巴拖向小值，如不及格率高的考试）：均值 < 中位数 < 众数。

这就是为什么看到"均值远大于中位数"时，你立刻能判断数据右偏——不需要画图。

### 另外两种平均数：调和与几何

除了均值、中位数、众数这三个"常用款"，教材里还会讲两个"特殊款"——它们在特定场景下才用，但考试常考。

#### [[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP02_调和平均数|调和平均数]]：已知金额、求平均价格

**什么时候用？** 你知道每批货的单价和总金额，但不知道买了多少斤。

**例子**：商人进三批鸡蛋：
- 第一批：10元/公斤，花了1000元
- 第二批：8元/公斤，花了1600元
- 第三批：12元/公斤，花了1200元

**怎么算平均价格？** 不能直接 (10+8+12)/3 = 10元——因为三批买的斤数不一样，第二批最便宜但买得最多，权重应该更大。

**正确做法**：先算每批买了多少斤：
- 第一批：1000 / 10 = 100公斤
- 第二批：1600 / 8 = 200公斤
- 第三批：1200 / 12 = 100公斤

总金额 = 3800元，总数量 = 400公斤
平均价格 = 3800 / 400 = **9.5元/公斤**

这就是加权调和平均数：$H = \dfrac{\sum m_i}{\sum (m_i/x_i)}$

> **论文里什么时候碰得到？** 基本碰不到。考试常考，论文里你用Stata算均值就完了。但你要知道：如果数据给的是"单价×金额"而不是"单价×数量"，就得用调和平均。

#### [[../../教材笔记/05_统计学原理/05_平均与变异指标/知识点/KP03_几何平均数|几何平均数]]：算平均增长率

**什么时候用？** 算平均增长率、平均利率、平均发展速度——只要是"利滚利"的连乘关系，就用几何平均。

**为什么不能用算术平均？** 举个例子：
- 某股票第一年涨100%（100→200）
- 第二年跌50%（200→100）

算术平均增长率 = (100% + (-50%)) / 2 = 25%
但你两年后还是100块，实际增长率 = 0%！

**算术平均严重高估。** 为什么？因为增长是连乘关系：
末值 = 初值 × (1+g₁) × (1+g₂) × …

要找一个"平均增长率G"，使得：
末值 = 初值 × Gⁿ

解得：G = ⁿ√(末值/初值)——这就是几何平均。

**例子**：GDP从2008年1000亿涨到2011年1360亿，三年平均发展速度是多少？
G = ³√(1360/1000) = ³√1.36 ≈ 1.108 = 110.8%
平均增长速度 = 110.8% - 100% = 10.8%

> **论文里什么时候碰得到？** 算"年均增长率CAGR"的时候。比如你写"2010-2020年中国GDP年均增长X%"，这个X就是用几何平均算的，不是把每年增长率加起来除以年数。

**三个平均数的大小关系**（对正数数据）：
调和平均 H ≤ 几何平均 G ≤ 算术平均 x̄

## 三、公式怎么来的？

### 均值为什么是"加起来除以个数"？

因为我们想找一个数，让它代表"所有人的平均水平"。

假设我们猜一个数 $a$，每个人和它的差距是 $x_i - a$。
如果我们把所有差距加起来 $\sum (x_i - a)$，让这个总和等于 0——意思是"高估的部分刚好抵消低估的部分"。

那：
$$\sum_{i=1}^{n} (x_i - a) = 0$$

展开：
$$\sum x_i - \sum a = 0$$

$\sum a$ 就是 $n$ 个 $a$ 加起来 = $n a$，所以：
$$\sum x_i - n a = 0$$

移项：
$$a = \frac{\sum x_i}{n}$$

**这一步是因为**：我们要求"高估等于低估"，解出来的 $a$ 就是均值。

### 中位数为什么要排序？

因为我们想找"一半人在它下面，一半人在它上面"的那个数。
不排序，你不知道谁在中间。
排序后，站中间的那个，自然就把人群切成两半。

## 五、一个完整的数字例子手算

**数据**：5 个同学的月生活费（元）：

```
1500  2000  2500  3000  8000
```

（第 5 个同学是富二代，每月 8000。）

### 算均值

$$\bar{x} = \frac{1500 + 2000 + 2500 + 3000 + 8000}{5} = \frac{17000}{5} = 3400 \text{ 元}$$

### 算中位数

已经排好序了，5 个数是奇数个，第 $(5+1)/2 = 3$ 个就是中位数：
$$M_e = 2500 \text{ 元}$$

### 算众数

每个数都只出现一次——**没有众数**（或者说每个数都是众数，没意义）。

### 解释结果

- 均值 3400 元：看起来"平均生活费 3400"。
- 中位数 2500 元：一半同学生活费低于 2500，一半高于 2500。

**哪个更能代表"大多数同学"？**

中位数 2500。因为 8000 那个富二代把均值拉高了——5 个人里有 4 个都低于 3400。

### Python 验证

```python
import numpy as np
from scipy import stats

data = [1500, 2000, 2500, 3000, 8000]

print(f"均值: {np.mean(data)}")        # 3400.0
print(f"中位数: {np.median(data)}")    # 2500.0
print(f"众数: {stats.mode(data, keepdims=True).mode[0]}")  # 1500（每个都只出现一次，取最小的）
```

## 六、组距数列怎么算？（考试重点）

上面的例子都是"未分组数据"——每个具体值都知道。但论文里你拿到的数据经常已经是分组好的了：

比如100个同学的身高，你不知道每个人具体多高，只知道：

| 身高组（cm） | 人数 |
|---|---|
| 150以下 | 4 |
| 150–160 | 16 |
| 160–170 | 40 |
| 170–180 | 30 |
| 180以上 | 10 |

这种情况下，均值、中位数、众数怎么算？

### 6.1 加权算术平均（组距数列）

**核心思路**：每组没有具体值，就用**组中值**代表这一组。

组中值 = (下限 + 上限) / 2

比如"160–170"这一组的组中值 = (160+170)/2 = 165cm。

开口组（"150以下""180以上"）借邻组组距推算：
- 150以下：邻组组距10，组中值 = 150 - 10/2 = 145
- 180以上：邻组组距10，组中值 = 180 + 10/2 = 185

**完整计算表**：

| 身高组 | 人数 $f_i$ | 组中值 $x_i$ | $x_i \times f_i$ |
|---|---|---|---|
| 150以下 | 4 | 145 | 145×4 = 580 |
| 150–160 | 16 | 155 | 155×16 = 2480 |
| 160–170 | 40 | 165 | 165×40 = 6600 |
| 170–180 | 30 | 175 | 175×30 = 5250 |
| 180以上 | 10 | 185 | 185×10 = 1850 |
| **合计** | **100** | — | **16760** |

$$\bar{x} = \frac{\sum x_i f_i}{\sum f_i} = \frac{16760}{100} = 167.6 \text{ cm}$$

> **为什么要加权？** 160–170组有40个人，它的"话语权"是150以下组（4人）的10倍。直接把5个组中值平均 = (145+155+165+175+185)/5 = 165，就错了——忘了乘人数。

### 6.2 众数（组距数列插值公式）

未分组数据直接数哪个值出现最多就行。组距数据不行——你得先找到**众数组**（人数最多的那一组），再用插值公式算出更精确的众数。

**步骤**：
1. 找众数组：人数最多的那一组（上面例子里是160–170组，40人）
2. 用下限公式：

$$M_o = L + \frac{\Delta_1}{\Delta_1 + \Delta_2} \times i$$

符号：
- $L$ = 众数组下限 = 160
- $\Delta_1$ = 众数组人数 - 前一组人数 = 40 - 16 = 24
- $\Delta_2$ = 众数组人数 - 后一组人数 = 40 - 30 = 10
- $i$ = 众数组组距 = 10

**代入计算**：
$$M_o = 160 + \frac{24}{24+10} \times 10 = 160 + 7.06 = 167.06 \text{ cm}$$

**直觉**：众数组像一座山峰的山顶。前一组人多（Δ₁小），说明山顶偏左；后一组人多（Δ₂小），说明山顶偏右。上面的例子里前一组16人、后一组30人——后一组人更多，说明众数偏右（靠近170那一侧），算出来167.06确实比组中值165偏右。

### 6.3 中位数（组距数列插值公式）

**步骤**：
1. 算累计频数，找到中位数落在哪一组
2. 中位数位置 = n/2 = 100/2 = 50

累计频数表：

| 身高组 | 人数 | 累计人数 |
|---|---|---|
| 150以下 | 4 | 4 |
| 150–160 | 16 | 20 |
| **160–170** | **40** | **60** ← 50落在这里 |
| 170–180 | 30 | 90 |
| 180以上 | 10 | 100 |

中位数在160–170组。

**下限公式**：

$$M_e = L + \frac{\frac{n}{2} - S_{m-1}}{f_m} \times i$$

符号：
- $L$ = 中位数组下限 = 160
- $n/2$ = 50
- $S_{m-1}$ = 中位数组前面各组累计频数 = 4+16 = 20
- $f_m$ = 中位数组人数 = 40
- $i$ = 组距 = 10

**代入计算**：
$$M_e = 160 + \frac{50 - 20}{40} \times 10 = 160 + 7.5 = 167.5 \text{ cm}$$

**直觉**：要走到第50个人的位置。前面已经有20个人了，还缺30个到达中点。这一组总共有40个人，所以在这一组里走了 30/40 = 75% 的位置，乘以组距10 = 走了7.5cm。

## 七、什么时候用哪个？

| [[01_数据长什么样|数据长什么样]] | 用哪个 | 为什么 |
|-------------|--------|--------|
| 对称分布，没有极端值 | 均值 | 均值利用了所有信息，最准 |
| 有极端值（收入、房价） | **中位数** | 均值被极端值带跑了 |
| 分类变量（性别、行业） | **众数** | 均值和中位数对分类变量没意义 |
| 定序变量（满意度等级） | 中位数 | 众数太粗，均值假设差距相等 |

---

## 八、易错点

1. **收入、房价、财富一定用中位数**。这些变量都是右偏分布（少数人特别有钱），均值会被拉高，不能代表"普通人"。
2. **分类变量不要算均值**。性别（男=1，女=0）的均值 = 女性比例，你可以说"女性占 47%"，但不能说"平均性别是 0.47"。
3. **均值和中位数差很多，说明数据偏了**。如果均值远大于中位数，说明右偏（有几个很大的极端值）；如果均值远小于中位数，说明左偏（有几个很小的极端值）。这时候你要回去看图，找原因。
4. **众数可能不存在或有多个**。连续数据一般没有众数（每个值都不同）；分类数据通常有众数。
5. **组距数列算均值忘了乘频数**。正确做法是 $\sum x_i f_i / \sum f_i$，不是把组中值直接平均。
6. **平均增长率用算术平均**。见股票例子：涨100%再跌50%，算术平均说涨25%，实际一分没涨。增长率必须用几何平均。
7. **已知金额求平均价格用算术平均**。给了单价和金额，得先算每批买了多少数量，再用总金额除以总数量——这就是调和平均。

## 九、Python 代码

```python
import pandas as pd
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['Hiragino Sans GB', 'PingFang SC']
plt.rcParams['axes.unicode_minus'] = False

# 假设有100个人的收入数据
data = pd.DataFrame({
    'income': [3000, 3500, 4000, 4500, 5000, 5500, 6000, 6500, 7000, 8000] * 10
})

# 加一个极端值：亿万富翁
data.loc[100] = 100000000

# 算三个统计量
print(f"均值: {data['income'].mean():.2f}")
print(f"中位数: {data['income'].median():.2f}")
print(f"众数: {data['income'].mode()[0]}")

# 画直方图看分布
plt.figure(figsize=(8, 4))
plt.hist(data['income'], bins=30, edgecolor='black')
plt.axvline(data['income'].mean(), color='red', linestyle='--', label=f'均值={data["income"].mean():.0f}')
plt.axvline(data['income'].median(), color='green', linestyle='--', label=f'中位数={data["income"].median():.0f}')
plt.xlabel('收入（元）')
plt.ylabel('人数')
plt.title('收入分布：均值 vs 中位数')
plt.legend()
plt.tight_layout()
plt.savefig('mean_vs_median.png', dpi=150)
plt.show()
```

**输出怎么读**：
- 红色虚线（均值）被亿万富翁拉到最右边；
- 绿色虚线（中位数）基本不动，还在大多数人所在的位置。
- 这张图就是你论文里"为什么用中位数"的最好证据。

| 统计量 | 优点 | 缺点 | 对极端值 |
|--------|------|------|----------|
| 均值 | 利用所有数据，最精确 | 被极端值拉偏 | 敏感 |
| 中位数 | 抗极端值，代表"中间" | 只用了排序信息，浪费数据 | 稳健 |

## 十一、速记卡

> **均值 = 加起来除以人数，敏感易被极端值带跑。**
> **中位数 = 排队站中间，抗极端值，收入房价用它。**
> **众数 = 出现最多的，分类变量用它。**
> **调和平均 = 已知单价+金额，求平均价格（论文少用，考试常考）。**
> **几何平均 = 算平均增长率/年均增速（CAGR必须用它）。**
> **组距数列三招**：均值用组中值加权平均，众数找众数组插值，中位数找累计50%位置插值。
> 看到均值远大于中位数 → 右偏，有大土豪。
> 看到均值远小于中位数 → 左偏，有大穷人。
> 三个平均数大小：调和 ≤ 几何 ≤ 算术。

## 💡 经济学视角：集中趋势——"平均工资"为什么总跟你感觉不一样？

**这个方法是为了解决什么经济学问题？**
每年统计局一公布"全国平均工资 9 万块"，评论区就炸了——"我又被平均了"。这就是集中趋势的核心矛盾：平均数告诉你一个"代表值"，但这个代表值可能根本代表不了大多数人。经济学家关心工资、收入、房价、消费支出，全都是右偏分布——少数富豪把均值拉高了，大多数人其实在中位数以下。到底报均值还是中位数，背后是"你想描述谁"的判断。

**经济学里哪些经典指标正好是它？**

| 指标 | 用哪个集中趋势 | 为什么 |
|---|---|---|
| 人均 GDP | 算术均值 | 本来就是总量÷总人口 |
| 居民工资 | 中位数 | 富豪拉偏均值，中位数才是"打工人工资" |
| 房价 | 中位数 | 豪宅把均值带飞，中位数反映刚需 |
| 家庭消费结构 | 众数 | 看最多家庭把钱花在哪类 |

**举个实证论文的例子：**
《中国城镇居民收入分布的变迁（1995—2020）》用 CHIP 数据发现：均值收入 25 年涨了 8 倍，但中位数只涨了 5 倍——均值涨得更快，说明顶部 10% 的人收入暴涨，把平均数字越拉越远。这就是为什么"被平均"的感觉越来越强。
